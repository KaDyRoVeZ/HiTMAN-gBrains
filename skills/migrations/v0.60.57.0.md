# Upgrade to v0.60.57.0: relationships with dates, live-by-default graph reads

Graph reads now return relationships that are true today, and a nightly check
closes jobs that cannot both still hold. Both change what the user sees, and the
nightly check makes small paid chat calls.

1. **Finish the upgrade.** `gbrain upgrade` runs it. To be sure, on the brain
   host:
   ```bash
   gbrain apply-migrations --yes --no-autopilot-install
   ```
   Migration v204 adds the relationship tables. Existing pages re-extract on the
   following dream cycles (bounded per cycle, no model calls), which records the
   dated evidence already in their timelines. Restart every `gbrain serve`,
   autopilot and worker.

2. **Relay the post-upgrade notice.** `gbrain post-upgrade` prints a one-time
   [AGENT] block. Show the user its message and ask whether to keep live-by-default
   graph reads and the nightly relationship check. Run its `if_no` commands only
   after they say no.

3. **Know what the nightly check does.** With the default utility model
   (`claude-haiku-4-5`, certified with 0 wrong closures in held-out runs) it writes
   each closure as an "(inferred) Ended <relation> [[target]]" timeline line. Show
   the user what it did and how to undo:
   ```bash
   gbrain edge-proposals list --status all
   gbrain edge-proposals undo <id>
   ```
   `gbrain config set dream.edge_contradictions.mode propose` makes it ask first.

4. **Use the new reads.** When a graph read leaves relationships out it returns a
   `former_relationships_hidden` notice with the exact call that shows them.
   History: `get_links { slug, status: "all" }`; a past date: `as_of: "YYYY-MM-DD"`;
   a period: `during: "2022"`. To record that a relationship ended, write
   `- **YYYY-MM-DD** | note — Ended works_at [[companies/x]]` on the person's
   timeline or call `add_link` with `valid_until`.

5. **Verify.**
   ```bash
   gbrain doctor --only edge_validity --json
   ```
   Guide: `docs/guides/temporal-edges.md`.
