# Upgrade to v0.60.63.0: retrieval feedback (opt-in) and declared single-value relations

Two additions, both off or review-only by default. Nothing changes for the user until they opt in.

1. **Finish the upgrade.** `gbrain upgrade` runs it. To be sure, on the brain host:
   ```bash
   gbrain apply-migrations --yes --no-autopilot-install
   ```
   Migration v207 adds the retrieval feedback tables (`retrieval_events`, `retrieval_event_pages`,
   `retrieval_event_links`, `retrieval_feedback`, `retrieval_weights`). They stay empty while feedback is off.

2. **Relay the post-upgrade notice.** `gbrain post-upgrade` prints a one-time [AGENT] block about retrieval feedback.
   Show the user its message and ask whether to turn it on. Only after they say yes:
   ```bash
   gbrain config set feedback.enabled true
   ```
   With it on, every `query`, `search`, `think`, `synthesize` and `recall` answer carries an `answer_id`; rate
   it with `rate_answer { answer_id, rating: 1-5 }` (or `gbrain rate <answer_id> <1-5>`) after you use it. Ratings
   nudge the ranking of the pages that answer used by at most 0.9x to 1.1x. Held-out tests with consistent
   ratings showed a gain on entity-centric brains and none on chat-history brains, so tell the user that.

3. **Single-value relations need a pack declaration.** A schema pack can mark a state relation
   `cardinality: one_per_from` (for example `works_at` meaning the one current employer). The nightly
   `edge_contradictions` phase then proposes closures for that type without a model call; nothing is written to
   pages until the user accepts one. No bundled pack declares a cardinality. Before activating a pack that does:
   ```bash
   gbrain schema cardinality-preview
   gbrain edge-proposals list
   ```

4. **Verify.**
   ```bash
   gbrain doctor --only retrieval_feedback_health --json
   gbrain feedback status --json
   ```
