# Upgrade to v0.60.45.0: automatic event extraction is on (auto_chronicle)

This release turns automatic event extraction back on, and on by default. When
the user saves a meeting, conversation or calendar page, gbrain turns it into
timeline events (`life/events/`) so `gbrain day <date>` can answer "what
happened". Each eligible page costs one paid chat call. Tell the user before
anything else in this file.

Anything that spends money needs the user's agreement. Never run
`gbrain chronicle-backfill` without `--dry-run`, or `gbrain dream --phase
chronicle`, on the user's behalf without asking.

1. **Finish the migration.** `gbrain upgrade` runs it. To be sure, run on the
   brain host:
   ```bash
   gbrain apply-migrations --yes --no-autopilot-install
   ```
   Schema migration v199 creates the `chronicle_page_state` ledger (the record
   of which page content was extracted) and the `chronicle_judge_reservations`
   table behind the daily limit. It rewrites no existing rows. Restart every
   `gbrain serve`, autopilot and worker.

2. **Relay the cost and ask.** Say to the user, with the real numbers from
   `gbrain doctor` (`auto_chronicle_default_on`):
   - Each new or changed meeting, conversation or calendar page dated within
     the last 30 days gets one chat call, capped at `chronicle.job_budget_usd`
     ($0.25 by default) per page.
   - At most `chronicle.auto_daily_limit` calls run per rolling day (200 by
     default). The worst case is limit x cap, $50 per day at the defaults. That
     is a per-page cap times a call count, not a daily budget; typical pages
     cost far less.
   - If gbrain has no price for the configured chat model, the per-page cap
     cannot apply. Calls still run, limited by the daily count. A cap the user
     sets explicitly refuses an unpriced model with `no_pricing` instead.
   - Page text is sent to the configured chat provider. Events from a private
     page stay private.
   - Pages already in the brain are not swept. Only pages written after this
     upgrade run automatically.

   Then record the answer. Either command clears the doctor and advisor
   notice:
   ```bash
   gbrain config set auto_chronicle true    # keep it
   gbrain config set auto_chronicle false   # opt out
   ```
   A brain that already had `auto_chronicle true` must ask too: that setting
   had no effect before this release.

3. **Know how it runs.** The chronicle phase of the maintenance cycle extracts
   pending pages. With autopilot running, nothing else is needed. On PGLite
   without autopilot, or to run pending pages now (paid):
   ```bash
   gbrain dream --phase chronicle
   ```
   No chat provider configured means nothing runs; doctor names the missing
   provider.

4. **Check one page.** After writing a meeting page, its write receipt carries
   `chronicle_backstop: { "pending": "next_cycle" }`, or
   `{ "skipped": "<code>", "why": ..., "fix": ... }`. After the phase runs,
   `gbrain day <date>` shows the events. Every code, its meaning and its fix
   are in `docs/guides/life-chronicle.md`.

5. **History is on request.** Backfill spends money. Preview it, show the user
   the count, and run it only if they agree:
   ```bash
   gbrain chronicle-backfill --since <YYYY-MM-DD> --limit 50 --dry-run
   ```

The opt-out is always `gbrain config set auto_chronicle false`. Unsetting the
key restores the default, which is on.
